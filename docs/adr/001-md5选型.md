# md5 选型：使用 ts-md5，在 Obsidian 渲染进程内完成

`${md5}` token 需要在 Obsidian 的**渲染进程**（renderer）中，对附件字节计算 MD5，并以 32 字符小写 hex 输出。决策采用 `ts-md5 ^1.3.1` 提供的 `Md5.hashAsciiStr(latin1-of-bytes)`，与 Node.js `crypto.createHash('md5')` 字节级等价，不暴露任何 format 配置。

## 上下文

`${md5}` token 的产物会**直接进入用户的附件文件名**——一旦发布实现，存量 vault 中所有使用过 `${md5}` 的文件名就已经固化为某一特定 MD5 十六进制序列，将来任何底层哈希实现上的漂移都会让 Obsidian 在重启时找不到这些附件，等价于数据丢失。`feat: md5` (0870a96) 的历史版本即采用 ts-md5，trading 仓库的 `cef77564ca0bd02f39980938b52afbbe.jpeg` 就是按该实现的输出命名的。

## 候选方案

### 候选 A：`ts-md5`（已采用）

纯 JavaScript MD5 实现在渲染进程直接可用，与 Node `crypto.createHash('md5')` 字节级等价（已用 trading 仓库 jpeg 的前 64 字节做 fixture 验证：MD5 = `841dac00b25fd23f976016396f5d3df9`）。代价：新增约 17 KB 的运行时依赖。

### 候选 B：`crypto.subtle.digest('MD5', buf)`

W3C Web Crypto 标准**未收录** MD5（明确列在不支持算法名单内）—— Chromium / Electron 渲染进程的 `crypto.subtle.digest('MD5', …)` 在实测中抛 `NotSupportedError: Unrecognized algorithm name`。**不可行**。

### 候选 C：经 Node 主进程的 `node:crypto.createHash('md5')`

技术上可用，但要求把 token 求值搬到主进程，跨进程 IPC 序列化 `ArrayBuffer`、每条 token 一次往返——主进程阻塞 / 崩溃会冻住整个插件，架构上的失败半径远超一个 token。代价过高。

### 候选 D：自实现 MD5

MD5 算法公开，约 300 行 TS，可去除依赖。代价：自维护一份密码学已破解的算法实现；且没有任何"少 17 KB 依赖"的真实工程诉求触发该路径。

## 决策

采用**候选 A**：`ts-md5 ^1.3.1`，入口固定为 `Md5.hashAsciiStr(Buffer.from(arrayBuffer).toString('latin1'))`。

输入编码选择 `latin1`（而非 UTF-8）的原因：MD5 是字节级算法，必须按字节喂入；`ArrayBuffer → Buffer → latin1 字符串` 是唯一能保证"每个字符码 = 对应字节值"且不被 Node 自动以 UTF-8 重解释的路径。该选择与 Node 原生 `crypto.createHash('md5').update(buffer).digest('hex')` 字节级一致。

token 故意不暴露 `format`（`case` / `length` 等）——历史版本曾有这些可配置项，但本仓库的 token 命名约定是"短名对应单义行为"，`${md5}` 只输出 32 字符小写 hex，避免用户把"摘要"误用为"短随机串"。

## 后果

### 正面

- 渲染进程内完成计算，零 IPC，零主进程风险。
- 与历史 `0870a96` 实现完全字节级一致，存量 vault 中已存在的 `${md5}` 附件命名继续有效。
- 实现是单一函数（`Md5.hashAsciiStr`），单元测试可锚定到一个具体 fixture（见下）。

### 负面 / 约束

- **依赖锁定到 `ts-md5` 的字节处理语义**。任何升级 / 替换如果把 `hashAsciiStr` 改成按 UTF-8 / byte-array / hex-string 喂入，存量文件名会漂移。**已用 `src/tokens/md5-token.test.ts` 中"用 trading jpeg 头 64 字节 → `841dac00b25fd23f976016396f5d3df9`"这条 fixture 测试做守护**——任何实现替换必须先重跑该测试，证明与 Node `crypto.createHash('md5')` 字节级等价，方可通过评审。
- **若 Electron 渲染进程某天支持 MD5 Web Crypto**（极端情况）：本 ADR 不阻止切换，但要求切换 PR 同步把 fixture 测试结果附在 PR 描述里，作为新旧等价性的显式证据。
- 多 17 KB 依赖；与"用主进程 IPC 换零依赖"对比，前者的失败半径仅限本 token，后者是整个插件。

### 退化路径

`getAttachmentFileContent()` 返回 `undefined`（典型场景：模板被求值时尚无对应附件字节可读）时，token 回退到 `crypto.randomUUID()` 并 `console.warn` 一次——模板仍能产出合法文件名，仅失去"内容寻址"语义。这条契约在 `md5-token.test.ts` 的 `should fall back to a UUID and warn once when no attachment content is available` 测试中锁定。
